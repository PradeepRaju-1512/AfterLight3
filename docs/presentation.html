3. Pillar 1 — Encapsulation & Invariants
backend/cpp/include/Board.hpp • Private State Protection
  • Private Member: std::array<Cell, 9> m_grid is private. Outside callers cannot directly modify array indices.
  • State Mutator Invariants: Every move must pass through Board::placeMark(position, mark):
    • Validates bounds ($0 \le \text{pos} \le 8$), throwing PositionOutOfBoundsException.
    • Validates cell is empty, throwing OccupiedCellException.
  • Defensive Copying & RAII: clone() returns an isolated value copy. Minimax lookahead simulations cannot corrupt the active game board.
void Board::placeMark(int position, Cell mark) { validatePosition(position); if (m_grid[position] != Cell::EMPTY) { throw OccupiedCellException(position, cellToChar(m_grid[position])); } m_grid[position] = mark; }
💡 Speaker Note: "Encapsulation ensures that invalid states cannot exist. In C++, private access specifiers protect the board array, and mutators enforce domain invariants with custom C++ exceptions."
4. Pillar 2 — Abstraction & Base Contracts
backend/cpp/include/Player.hpp • Pure Virtual Interface
  • Pure Abstract Class: Player contains a pure virtual destructor and pure virtual member function.
  • Interface Contract: Enforces virtual int getMove(const Board& board) = 0;.
  • Caller Decoupling: The Game class only depends on this abstract interface. It has zero knowledge of whether the move comes from a human click, a random number generator, or a minimax search algorithm.
class Player { protected: std::string m_name; Cell m_mark; public: Player(std::string name, Cell mark) : m_name(std::move(name)), m_mark(mark) {} virtual ~Player() = default; virtual int getMove(const Board& board) = 0; // Pure virtual contract };
💡 Speaker Note: "Abstraction establishes the contract. In C++, pure virtual functions (= 0) guarantee that every derived player must provide a concrete getMove implementation."
5. Pillar 3 — Inheritance & Specialization
Clean Subclass Hierarchy across Players & Bots
Player (Abstract Base) / \ HumanPlayer BotPlayer (Abstract Subclass) / | \ RandomBot StrategicBot UnbeatableBot
  • HumanPlayer: Inherits identity attributes and implements getMove() via a queued move buffer.
  • BotPlayer: Subclasses Player, adding bot difficulty ratings and the pure virtual explainDecision() method.
  • Concrete Bots: RandomBot (Wanderer), StrategicBot (Sentinel), and UnbeatableBot (The Unbroken) each specialize the move selection algorithm.
💡 Speaker Note: "Inheritance allows code reuse for player names, marks, and getters, while derived classes specialize decision algorithms in C++."
6. Pillar 4 — Polymorphism & Vtable Dynamic Dispatch
Uniform Execution Without Conditional Branching
  • Dynamic Method Dispatch: In Game::makeMove(), the engine simply calls:
    int chosen_move = m_currentPlayer->getMove(m_board);
  • Vtable Resolution: The call is resolved at runtime via the virtual method table (vptr/vtable) with zero conditional branch overhead.
  • Open/Closed Principle (OCP): A student could add a 4th bot (e.g. Monte Carlo Tree Search) by simply subclassing BotPlayer, without changing a single line of code in Game or Board.
💡 Speaker Note: "In C++, dynamic dispatch is achieved via the Virtual Method Table (vtable). At runtime, the C++ runtime uses the object's vptr to execute the overridden method in 0.28ms."
7. Composition over Inheritance & SOLID
High Cohesion, Loose Coupling & Design Patterns
  • Composition: Game does not inherit from Board. Instead, Game has-a Board and has-a two Player instances.
  • Design Patterns:
    • Strategy Pattern: Bots encapsulate interchangeable move calculation algorithms.
    • Factory Method: BotFactory.create_bot(difficulty) centralizes instantiation.
    • Repository Pattern: IGameRepository decouples business logic from SQLite.
    • State Pattern: GameStatus enum manages match lifecycle states.
💡 Speaker Note: "Composition allows the Board to be cloned independently during Minimax lookahead without copying the outer Game aggregate."
8. Unbeatable Minimax AI with Alpha-Beta Pruning
backend/engine/bots.py • Mathematically Solved Game Theory
  • Recursive Game-Tree Search: Evaluates all possible future board states assuming rational opponent play.
  • Depth-Discounted Utility:
    • Win: $+10 - \text{depth}$ (incentivizes faster wins).
    • Loss: $-10 + \text{depth}$ (delays inevitable losses).
    • Draw: $0$.
  • Alpha-Beta Pruning: Maintains $\alpha$ (max guaranteed score) and $\beta$ (min guaranteed score). Whenever $\beta \le \alpha$, suboptimal subtrees are pruned, reducing search time by up to 80%.
  • Unbeatable Guarantee: Mathematically proven to never lose. 100% win or draw against any human player.
💡 Speaker Note: "Tic-Tac-Toe is a solved game. Minimax with alpha-beta pruning searches the tree and guarantees the mathematically optimal move."
